---

## Taxonomy: Three-Tier Selector Strategy

### Tier 1: TEXT-LABEL (Primary) ← Snapshot-based, DOM-agnostic, bilingual
- Method: Accessibility tree text pattern matching
- Pattern: `snapshot.includes('button "label"')`
- Resilience: Very High (structure-independent)
- Coverage: All three files
- Example: `snapshotText()` → `labelMatches(entry.label, LABELS.send)`

### Tier 2: DATA-TESTID (Secondary) ← CSS selectors, live DOM queries
- Method: Direct `[data-testid="..."]` attribute targeting
- Usage: Message extraction, file upload, form input
- Resilience: High (attribute-based, not text-dependent)
- Coverage: pages/chatgpt/chatgpt.selectors.ts (CHATGPT_SELECTORS)
- Example: `[data-testid="send-button"]`, `[data-message-author-role="assistant"]`

### Tier 3: REF-BASED (Tertiary) ← Snapshot references, browser automation
- Method: Direct browser action via snapshot entry refs
- Usage: Artifact download, message interaction, direct clicks
- Resilience: Very High (immutable snapshot references)
- Coverage: ChatGPTJobRunner.ts, worker/run-job.ts
- Example: `browser.clickRef(entry.ref)`, `browser.downloadByRef(entry.ref)`

## Key Findings

### ✅ Strengths
1. **Hybrid approach is robust:** TEXT-LABEL primary ensures resilience to HTML changes; DATA-TESTID secondary handles edge cases
2. **Multilingual support:** 100% English/Spanish coverage across all primary labels
3. **No critical bugs:** Selector logic is sound and well-tested
4. **Strategic use of data-testid:** Only used where snapshot insufficient (message extraction, file upload)
5. **Good separation of concerns:** Selectors abstracted into chatgpt.selectors.ts; orchestration in ChatGPTJobRunner.ts

### ⚠️ Minor Issues (Non-blocking)
1. **Duplication:** MODEL_FAMILY_PREFIX and EFFORT_LABELS defined in two places
   - Location: ChatGPTJobRunner.ts + worker/run-job.ts
   - Impact: Low (values are immutable)
   - Fix: Extract to chatgpt.selectors.ts

2. **Hardcoded regex:** `snapshotShowsCompletedResponse()` uses regex instead of label lookups
   - Current: `/Stop streaming|Detener la transmisión|.../i.test(snapshot)`
   - Better: Use LABELS.stop array instead
   - Impact: Low (works correctly but inconsistent pattern)

3. **Label discrepancy:** `modelSelector` not in ChatGPTJobRunner.LABELS override
   - Actual: Only available via DEFAULT_LABELS spread
   - Impact: Very Low (works correctly, rarely used)

## Hardcoded Selectors vs. Data-Testid Usage

### Text-Label Selectors (Snapshot-based)
- **Strength:** Language-agnostic, structure-independent
- **Implementation:** Array of multilingual strings matched via `includes()`
- **All three files:** Use this as PRIMARY approach
- **Example:** `LABELS.send = ["Send prompt", "Send message", "Enviar prompt", "Enviar mensaje", "Enviar"]`

### Data-Testid Selectors (DOM-based)
- **Strength:** Direct, fast, not text-dependent
- **Files:** pages/chatgpt/chatgpt.selectors.ts (CHATGPT_SELECTORS constant)
- **Usage:** Only for message extraction, file upload, model selection
- **Examples:**
  - `[data-testid="send-button"]`
  - `[data-testid="attachments-button"]`
  - `[data-message-author-role="assistant"]`
  - `[data-testid="model-selector"]`

### Strategic Separation
- **Snapshot + Text Labels:** 80% of interactions (buttons, form fields)
- **Data-Testid:** 15% of interactions (message extraction, file upload)
- **Ref-Based:** 5% of interactions (direct browser actions, downloads)
